# ADR-004：v1 不内置完整 eD2K 协议栈，跨协议补源排 v2

| 项 | 值 |
| :--- | :--- |
| 状态 | **已接受**（M5 前复核） |
| 决策者 | 架构组 / 内核组 |
| 相关 | [LLD §5.8](../../03-design/LLD.md) · [RISK R-10](../../05-quality/RISK.md) · [ROADMAP M5](../../06-plan/ROADMAP.md) |

## 背景

讨论中曾设想「从 eD2K 网络补齐 BT 缺失分片」，以及实现类似 BitComet 长效种子的跨协议补源。 attractive，但存在硬性技术壁垒：

- eD2K 使用 **MD4 / 固定 9.28 MB 分块**，BT 使用 **SHA-1 / 动态分片**，两者边界完全不对齐。
- 补源必须先取回 eD2K 分块，再本地重算 BT 分片 SHA-1，校验通过才能拼接写入。这个「哈希转译层」的计算与实现成本远高于协议封装本身。
- v1 的核心假设只有一个：**KAD 发现 → 唤醒 → 复活**。任何不服务于该假设的功能都会放大 M1 的验证周期。

## 选项

| 选项 | 评价 |
| :--- | :--- |
| A. v1 内置完整 eD2K 栈 + 补源 | 范围失控，MVP 无法收敛，否决 |
| B. v1 完全不碰 eD2K | 后续加 `ed2k_hash` 需要全量重算文件，浪费，否决 |
| C. **v1 只计算并入库 `ed2k_hash`，预留接口；全栈与补源排 v2** | 成本极低、保留演进空间，**采纳** |

## 决策

- M-02 在 v1 即计算 eD2K（MD4 根哈希）并写入 [DATA 数据模型](../../03-design/DATA.md) 的 `files.ed2k_hash` 字段，AICH 可不做。
- M-12 `cr-ed2k` 跨协议补源列为 **P2 / v2**，进入 M5 前须独立评审投入产出比，并新增 ADR。
- 私有唤醒协议的 `capabilities.ed2k` 字段 v1 固定为 `false`。

## 后果

- 正面：MVP 范围可控，`ed2k_hash` 免去重算；兼容 eMule 文件索引字典的 Key 语义得以保留。
- 负面：v1 无法从 eD2K 网络补源，冷门资源仍完全依赖 BT Swarm 中被唤醒的节点。
- 风险：R-10 分块不对齐可能导致 v2 返工，M5 前复核。

## 2026-11-11 复核：本决策的排期部分被 [ADR-011](ADR-011-ed2k-interop.md) 取代

项目所有者决定把「兼容旧客户端」的优先级提到最高（D1–D4），因此：

- **仍然有效**：M-02 在 v1 计算并入库 `ed2k_hash`（这是双向互操作唯一的连接点，现已兑现价值）；
  不实现 AICH；哈希转译（MD4 9.28 MB ↔ BT 动态分片）仍排 P2 / v2，仍须在 M5 前独立评审。
- **被取代**：「v1 不内置 eD2K 栈、全栈排 v2」。标准 eD2K 下载与上传栈改由 ADR-011 排入 v1（L2），
  理由是冷启动需要复用 eMule 的既有资源圈，且该文件始终是**本机磁盘**上的，
  不需要跨协议哈希转译即可作为标准 eD2k 源提供（ADR-011 §L3 审查）。
- **仍属非目标**：完整 eMule 积分 / 排队 / 上传信用体系；最小上传队列属传输栈，仍需实现。
- 复核记录见 [ADR-011 背景](ADR-011-ed2k-interop.md)，风险侧见 [RISK R-10](../../05-quality/RISK.md)。
