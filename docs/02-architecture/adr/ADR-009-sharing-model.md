# ADR-009：常态共享目录与按需唤醒分层并存

| 项 | 值 |
| :--- | :--- |
| 状态 | **已接受** |
| 决策者 | 产品 / 架构组 |
| 相关 | [LLD §5.6](../../03-design/LLD.md) · [PRD P4 / DR-01](../../01-product/PRD.md) · [FLOWS F1/F3/F6](../../03-design/FLOWS.md) |

## 背景

讨论中出现一次关键摇摆：最初设计依赖「私有唤醒 RPC」按需激活冷节点，后来提出「像 eMule 一样把文件放进共享目录就常态共享」，两者一度被视为互斥方案。

- **只做常态共享**：1 万个文件全量做种会撑爆内存与连接数，违反 [SRS NFR-01/03](../../01-product/SRS.md)。
- **只做按需唤醒**：用户必须主动「声明共享」，体验退化为手动管理种子，失去 eMule 式直觉。
- 还有一个隐藏硬壁垒：**BT 基于种子而非文件**，仅有文件本身无法下载（缺分片大小与每片 SHA-1）。

## 选项

| 选项 | 评价 |
| :--- | :--- |
| A. 纯按需唤醒 | 体验差、违背产品初衷，否决 |
| B. 纯常态全量做种 | 资源不可控，否决 |
| C. **双层模型：体验层常态共享 + 实现层按需唤醒** | 两者分工，**采纳** |

## 决策

| 层 | 用户/系统看到什么 | 实现 |
| :--- | :--- | :--- |
| 体验层 | 文件放进共享目录即「永久在线、可被搜到」 | 自动索引、自动发布 KAD 影子索引、通告不撤销 |
| 实现层 | 只有被请求时才真正做种 | LRU 活跃池（默认 50）、握手拦截、空闲 10 min 切出 |

配套三项必须同时落地，否则模型不成立：

1. **伴随种子生成**（[LLD §5.2](../../03-design/LLD.md)）：文件入库即生成标准 `.torrent`，补齐 BT 分片元数据。
2. **影子索引**（[LLD §5.3](../../03-design/LLD.md)）：休眠后仍保留索引行与 DHT 通告，物理休眠、逻辑在线。
3. **被动唤醒**（[FLOWS F5](../../03-design/FLOWS.md)）：旧客户端直接发起标准握手也能触发切入，无需理解私有协议。

## 后果

- 正面：用户获得 eMule 式直觉，系统资源有界；对旧客户端完全透明。
- 负面：状态机与调度复杂度上升；切入/切出需加滞回抑制抖动。
- 约束：会话硬顶 `wake_session_ttl = 2 h`，防止异常请求长期占用活跃池。
