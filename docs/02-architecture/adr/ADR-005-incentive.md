# ADR-005：贡献积分与全局信用体系后置到 P2

| 项 | 值 |
| :--- | :--- |
| 状态 | **待定**（M4 定稿） |
| 决策者 | 产品 / 架构组 |
| 相关 | [LLD §5.13](../../03-design/LLD.md) · [RISK R-01](../../05-quality/RISK.md) · [PRD C8](../../01-product/PRD.md) |

## 背景

讨论中观察到：eMule 的积分/排队体系奖励长期共享，BT 的 Tit-for-Tat 奖励快速交换，后者是冷门资源死种的根本原因之一。因此有人提出在 ColdRevive 引入跨会话的贡献信用（做种时长、被唤醒次数、成功传输量）来激励长期在线。

但信用体系会立刻引入三个新问题：女巫攻击伪造贡献、刷分（自唤醒自下载）、以及「新节点零信用导致无法被服务」的二次冷启动。hMule 的失败已经证明，在网络效应尚未建立时叠加复杂激励只会增加失败模式。

## 选项

| 选项 | 评价 |
| :--- | :--- |
| A. v1 内置完整积分体系 | 抗女巫未解即上线，风险过高，否决 |
| B. 永不引入 | 长期留存可能缺少抓手，暂不否定 |
| C. **后置 P2，先靠产品机制破局** | 与冷启动策略解耦，**暂定采纳** |

## 决策

**暂定选项 C**：v1 不引入全局信用，仅保留 `peers.reputation` 字段做**本地**信誉评分（用于结果排序与黑名单，不跨节点同步）。

v1 的激励替代方案是产品级机制：

1. 单机价值优先——全网只有一个节点时仍是可用的个人去中心化归档工具。
2. 下载即贡献——完成的文件自动进入共享目录并发布索引（[FLOWS F4](../../03-design/FLOWS.md)）。
3. 生态借力——兼容 aria2/AriaNg 插件与公共 KAD，不靠积分拉新。

M4 公测后，若留存数据表明需要激励，须先完成抗女巫与信用伪造方案，再以新 ADR 取代本决策。

## 后果

- 正面：v1 攻击面小、冷启动路径简单；本地信誉即可满足 [SRS FR-09](../../01-product/SRS.md) 的过滤需求。
- 负面：长期在线缺乏显式回报，可能影响重度分享者留存，需在 M4 用数据验证。
- 约束：引入任何跨节点信用前，必须更新威胁模型（[LLD §5.11](../../03-design/LLD.md)）。

## 复核时点

M4 公测留存数据出炉后。
