# ADR-012：R-04 改为「尽力」——取消公网可达率的数值承诺

| 项 | 值 |
| :--- | :--- |
| 状态 | **已接受**（2026-11-16 项目所有者决定） |
| 决策者 | 项目所有者 / 架构组（记录） |
| 相关 | [RISK R-04](../../05-quality/RISK.md) · [nat-matrix.md §19](../../../tests/spikes/s6/nat-matrix.md) · [ROADMAP](../../06-plan/ROADMAP.md) · [SRS A4](../../01-product/SRS.md) |

## 背景

S6 的验收口径里曾有一条 `R-04 ≥ 70%`：四类真实 NAT（含 CGNAT）的唤醒可达率要达到 70%，
代码里对应常量 `R04_MIN_REACHABILITY = 0.70`，矩阵配置里对应 `r04_min_reachability: 0.7`。

2026-11-16，项目所有者明确否定了这个口径：

> 我们不能承诺具体数字，只能是尽力，我们是提供一个可能性，不是确保实现，也没必要。

这个判断是对的，理由比「做不到」更根本：

1. **产品卖的不是百分比**。ColdRevive 提供的是「除在线唤醒之外，多一条能叫醒机器的路」。
   用户要的是「叫得醒 / 叫不醒时我知道为什么」，不是「你们保证 70% 叫得醒」。
2. **数字会反过来污染测量**。阈值一旦存在，「测不到 70%」就会被读成「不合格」，于是产生两种
   坏激励：为凑数字去挑环境，或把没测到的格子填成「看起来通过」——后者正是本项目一直在打的
   那类缺陷（见 nat-matrix.md §17.6、§18.3）。
3. **分母不可控**。「公网可达率」的分母是「所有家用 NAT」，而这个总体无法抽样：不同运营商、
   不同型号光猫、不同月份的策略都不同。用 5 个样本算出来的百分比不具备统计意义，
   却会被当成 SLA 引用。

## 决策

**取消 R-04 的一切数值承诺，改为「尽力（best-effort）」。**

具体落地（都是可检查的，不是表态）：

| 位置 | 改动 |
| :--- | :--- |
| `src/crates/cr-nat/src/lib.rs` | 删除 `R04_MIN_REACHABILITY`；新增 `R04_STANCE = "best-effort"` 与 `R04_NUMERIC_COMMITMENT: Option<f64> = None`（**保留字段名是为了让机器读到「我们明确选择不给数」，而不是以为漏了**）；新增单测 `r04_has_no_numeric_commitment` 防止阈值被好心加回来 |
| `tests/spikes/s6/nat_matrix_config.json` | `r04_min_reachability: 0.7` → `r04_stance` / `r04_numeric_commitment: null` / `r04_requirement`（文字承诺）/ `s6_pass_criteria`（四条定性判据） |
| `tests/spikes/s6/nat_matrix.py` | 聚合报告不再输出阈值比较，改输出 `r04_stance` + `reachability_note`（可达率是**描述性统计**）；自检新增 `r04_has_no_numeric_threshold` |
| [RISK R-04](../../05-quality/RISK.md) | 触发条件由「公网可达率 <70%」改为「**某类环境中直连与中继回退同时失败**」 |
| [TEST](../../05-quality/TEST.md) / [TECH-STACK](../TECH-STACK.md) / [OPEN-QUESTIONS](../../06-plan/OPEN-QUESTIONS.md) | 同步为定性口径 |

## S6 现在的验收口径（替代 70%）

不再是「打通的百分比够不够」，而是**四条定性要求**：

1. 5 类环境（4 类 NAT + CGNAT）各有 ≥1 份 `evidence_valid=true` 的逐类报告；
2. 每类 `direct` 与 `relay` 两条路径各 ≥30 次真实观测，成功判据是收到真实 `WAKEUP_ACK`；
3. `direct` 失败的环境里 `relay` 必须送达；两条都失败的记为该类不可用，**作为已知限制写进报告**
   （「这一类只能中继」是合格结论；「没测」不是）；
4. 结论由执行人依证据手工回填，脚本永不置 pass。

换句话说：**要的是「每一类会怎样」这件事被查清，不是「总体够不够好」。**

## 后果

- 不再需要为凑百分比挑环境：矩阵的作用从「达标线」变回它本来的样子——**地图**。
  少一类就是地图上缺一块，标出来即可，不必为了让数字好看去造样本。
- 中继回退从「触发式加码」改为**常开**：以前是「达标率低才提中继优先级」，现在没有阈值可触发，
  所以策略上直接按「对称/CGNAT 走中继」执行，不再等一个永远不会到来的触发条件。
- 对外表述统一为：**提供一条可行的路，失败时可解释、可感知**；不出现任何可达率承诺。
- 仍然保留的强度：**证据纪律一条不松**。取消的是「达标数字」，不是「必须实测」。
  `S6.status` 仍 `not_run`，`g2_claim=false`，R-04 在 `spikes.json` 里仍是「待实测」状态。

## 未一并修改的相邻项（需所有者另行决定）

产品层还有一条同类承诺：[PRD](../../01-product/PRD.md)「死种复活成功率：受控环境 100%，
公开网络 ≥ 90%」与 [SRS §2.4](../../01-product/SRS.md) 的验收口径。它与「NAT 可达率」不是同一个指标
（复活成功率还含 tracker 命中、元数据、做种在线等环节），且受控环境 100% 是 M1 已实测的硬指标。
本 ADR 只处理 R-04；是否把「公开网络 ≥ 90%」也改为尽力口径，留给所有者决定。
