## 决定 1：EX-1 公平性这一版怎么办（有到期日，最急）

**一句话问题**：M3 版要不要为「慢链路公平性 78/80」再花一轮重测，还是书面把义务推到 M4？

**为什么卡在你这**：EX-1（`G2-FAIRNESS-EXCEPTION-2026-11-25.md`）第 3 节 C4 写的是
「**下一版**义务：先登记新判据，再采样本」，而 C3 的失效条件里**没有**「时间过去」。
严格讲 v2.4.161 一发布就等于到了「下一版」。要么做，要么你自己签字延期——我不能自己延。

**已知事实**：判据 sha `0671a173…` 未改；80 轮 78 过，两条失败轮 `0.430/0.570`、`0.433/0.567`；
归因 `r(丢包差, 份额偏移) = −0.706`，中继 `shaping/dropped/limited` 全 0 ⇒ 不是限流、不是量具偏心。

| 选项 | 利 | 弊 |
| :--- | :--- | :--- |
| **A. 实现 LEDBAT** ＋ 新 ADR-025 ＋ 新判据 ＋ 重采 | 真解决慢链路分账偏移；C4 一次结清；provenance 三项（`git_commit` / `kernel_release` / `tc_qdisc_and_class`）能补齐 | 工作量最大：拥塞控制本身 + 与 relay 令牌桶交互；LEDBAT 对 Cubic/Reno 让得过狠会掉吞吐；要重搭 netem 环境；判据必须先登记，不能看结果改 |
| **B. 不实现，只换一套更宽的判据重采** | 便宜、快 | 这就是 C4 第 5 条明令禁止的「改阈值去解释已有数据」。除非你明确说「这是重新定义产品可接受范围」并走 ADR，否则拿不到正当性，只能算放水 |
| **C. 书面延期到 M4，本轮不动**（推荐） | 零成本、零风险、完全诚实；C1/C2/C5/C6 继续有效，措辞一字不改 | 这是第二次把义务往后推（第一次是 11-25 那版），要你签字写明到期点；M4 前必须做，否则例外失效 |
| **D. 把公平性从承诺里删掉** | 一劳永逸，不再有债 | 直接改产品承诺；G2 出口记录的措辞要跟着重写；等于对外说「不保证公平」 |

**建议：C。** 理由：A 不是一天能做完的事，而 C4 要的是「判据先于样本」，赶工只会得到一份
不可信的新证据；B 是禁路。C 只要一份签字。

**不决定的后果**：v2.4.161 一旦发出，EX-1 在技术上过期，G2 出口记录里「带例外关闭」这一行
要回退成「未决」——比现在难看，而且是被动发生的。

## 决定 2：W6.6 的 GUI 走哪条路

**一句话问题**：托盘 / 浏览器下载捕获 / UPnP 续租这三件，这版做、下版做、还是不做？

**为什么卡在你这**：三件都要引入新依赖或新的平台 API，属于「选路线」不是「写代码」。
ADR-003 只写「Tauri 外壳**或**浏览器页面」，两者一直没选。

**已知事实**：Web UI 已经能用（`src/crates/cr-api/src/webui.rs`，143 行，同源 `/` + `/ui/app.js`
+ `/ui/style.css`，任务列表 / `addUri` / 暂停恢复）；`coldrevive-agent` 目前只是无 GUI 看护内核
（spawn / 巡检 / 按预算重启 / 只读 `/health`）；S6 已实测本机 IGD 与 NAT-PMP **不可用**，
UPnP 续租在当前环境无法验证。

| 选项 | 利 | 弊 |
| :--- | :--- | :--- |
| **A. Tauri 桌面包** | 托盘、捕获、安装包一次到位，符合 ADR-003 提法 | 引入 Node + webkit2gtk 系统依赖，CI 与包体都上一台阶；Linux 托盘要 libappindicator，无头机测不了；macOS 签名/公证要证书；工程量最大 |
| **B. 纯 Web UI + 系统服务，不做托盘**（推荐） | 零新依赖，现有 UI 直接升级；跨平台一致；打包就是单二进制 + systemd/launchd | 没有托盘图标；浏览器捕获做不了（那要浏览器扩展，属 W6.5 P2）；用户得自己开页面 |
| **C. 轻量原生托盘**（`tray-icon` / Linux `ksni`） | 单二进制、无 Node、托盘有了 | 三平台各一套 API（Win32 / NSStatusItem / StatusNotifierItem）；Linux 依赖 DBus 与状态栏宿主；等于把 GUI 塞进 agent 进程，测试面变大 |
| **D. 明确移出**：W6.6 只保留看护内核，三件移到 M4/后续 | 立刻不用纠结，文档诚实 | M3 交付物清单少一项（不挡 G3）；产品形态不完整 |

**建议：B + D 组合。** 本轮把 Web UI 补成能交付的样子（不需要新依赖），托盘 / 捕获 / UPnP
三件明确移出并写进 ROADMAP；等真有桌面分发需求再做 A。

**不决定的后果**：W6.6 一直半开，每轮复盘都要重复解释一次；而且没有 GUI 就没有真实用户，
M4 的公测准备会卡在同一个地方。

## 决定 3：FR-25 要不要碰公共 DHT

**一句话问题**：双轨 key 已经进了本地发布帧，但「向公共 DHT announce」这件事必须你授权，我不动。

**为什么卡在你这**：这是对外部世界产生副作用、且不可撤回的动作（记录一旦扩散无法收回），
按现有纪律必须所有者明确授权，不能因为本地接线完成就视作已授权。另外 R-02 要求 M4 前
用实测拒绝率复审「双轨发布量翻倍」，这个前置条件还没做。

| 选项 | 利 | 弊 |
| :--- | :--- | :--- |
| **A. 只对自有/测试 DHT 节点，永不 announce 公共 DHT**（推荐，M3 阶段） | 零法律与滥用风险；自有节点已能验证双轨发布 | FR-25 公网侧仍无证据，只能记 BLOCKED 到 M4 |
| **B. 授权 announce 公共 DHT**，带限速 + 可远程关闭开关 | 能拿到真正的公网证据 | 发布量翻倍；污染公共 DHT 的风险由你承担；被投诉也无法撤回已扩散的记录 |
| **C. 明确声明 FR-25 公网侧 N/A** | 不用再挂账 | 产品声明缩水，SRS 要改 |

**建议：A。** 理由：M3 的目标是「生态兼容」不是「公网铺开」；R-02 的拒绝率复审还没做，
这时候 announce 等于跳过前置条件。

**不决定的后果**：FR-25 公网侧继续 BLOCKED——不挡任何门，但 M4 一到就变成硬阻塞。

## 决定 4：macOS 的 NFR-02 怎么记（最不急）

**一句话问题**：macOS 真机 5 pass / 1 not_verified，那 1 项要不要补测后计入？

**那一项是什么**：「唤醒线程逐线程优先级」。**不是 fail**（没观察到降级），**也不是 pass**
（没拿到逐线程读回值），因为测试包里没有 macOS 可用的逐线程读取器。按 DOC-34 §10 必须如实保留。

**已知事实**：Linux 侧探针是现成的（`scripts/nfr02_thread_prio_probe.py` 读
`/proc/<pid>/task/<tid>/stat` 的 priority / nice / policy 逐线程判定）。macOS **没有 `/proc`**，
要拿同样的证据得走另一套机制：进程内调 `pthread_getschedparam`，或进程外用
`task_for_pid` + `thread_info(THREAD_SCHED_INFO)`——后者需要 entitlement / 提权，未必一次能读到。

| 选项 | 利 | 弊 |
| :--- | :--- | :--- |
| **A. 补测**：写 macOS 逐线程读取器（进程内 `pthread_getschedparam` 或 `thread_info`），重跑 run3（推荐但可缓） | 唯一能把 macOS 干净计入的路径；读取器本身可复用 | 改代码 + 重新打包 + 真机再跑一轮；`task_for_pid` 要 entitlement / 提权，不保证一次拿到值 |
| **B. 书面定口径**：如实保留 5 pass / 1 not_verified，不计入 NFR-02 达标声明（现状态） | 零成本，措辞已经准确 | NFR-02 只能说「Linux/Windows 两平台实测」，macOS 永远是附注 |
| **C. 直接写「macOS 已验证」** | 好看 | **这是伪造**：1 项没有证据。我不会做，也不建议你签 |

**建议：B 现在、A 有条件时做。** B 的措辞本来就是准确的，不改也不损失；A 的收益是把 macOS
从「附注」升成「实测三平台」，值得做但不紧急。

**不决定的后果**：维持现状（即 B 的措辞），没有任何损失。四项里唯一可以不表态的一项。

## 决定 5：M4 要不要把三项移出功能重新纳入（待签）

**一句话问题**：M4 只做 G4 门槛（A），还是把托盘 / 浏览器下载捕获 / UPnP 续租也纳入交付（B/C/D）？

**为什么卡在你这**：这三项在决定 2 已被明确移出 M3，挂「M4 再评估」。是否重新纳入属于产品范围选择；
三项分别要新 GUI 依赖、浏览器扩展分发、真实网关环境，我无权自行扩大 M4 WBS。
展开范围见 [DOC-38 M4 范围与 R-02 复审启动](M4-SCOPE-2026-11-28.md)。

| 选项 | 利 | 弊 |
| :--- | :--- | :--- |
| **A. 只做 G4 核心**（推荐） | 范围与门禁一一对应；安全 / KPI / 法务 / R-02 / R-11 能集中收口；维持零新 GUI 依赖 | 公测形态只有 Web UI + 系统服务；用户要自己开页面，没有托盘和自动下载捕获 |
| **B. 只加 UPnP 续租** | 映射到期可自愈，减少长期依赖 relay；`cr-nat` 已有原语 | 本机 IGD / NAT-PMP 实测不可用，需先找真实网关并补续租 / 回落判据；多一条 M4 验收线 |
| **C. 只加系统托盘** | 桌面用户有常驻入口和异常提示，公测体验完整 | 三平台各一套 API，Linux 依赖 DBus，macOS 需签名 / 公证；把 GUI 依赖重新引进来 |
| **D. 三项全做** | 三进程模型名副其实，公测最接近成品 | 工作量最大；浏览器捕获是 FR-22 P2 / W6.5，扩展分发与权限另算；会挤压 G4 安全与法务窗口 |

**建议：A。** 理由：G4 本身已有安全测试、72 h Soak、公测 KPI、书面法务意见与 R-02 复审五条线；
三项里两项缺环境或依赖，一项是 P2。决定 2 刚签完 B+D，立刻回扩范围会让 M4 失去可验收边界。

**不决定的后果**：按 A 默认执行——三项保持「M4 再评估」但不纳入交付，不阻塞 G4；
若到公测前才提出要托盘或捕获，会变成临时插队并挤压安全 / 法务窗口。

## 附：以后我提决定时固定用这个格式

1. **一句话问题**——用「要不要 / A 还是 B」的问句，不用「口径未决」「待裁定」这类词；
2. **为什么卡在你这**——写明是我没权限、还是需要签字、还是需要选技术路线；
3. **选项表**——每项都写利与弊，禁止只写利；
4. **我的建议 + 理由**——必须给，不要让你在四个选项里裸选；
5. **不决定的后果**——写明是「停在这里」还是「会过期」还是「会变成 M4 的硬阻塞」。
