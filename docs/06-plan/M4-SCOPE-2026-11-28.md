## 1. G4 门槛具体是什么

G4 在 [ROADMAP §3](ROADMAP.md) 与 [TEST §6](../05-quality/TEST.md) 的原文只有三句：
**安全测试全通过、公测 KPI 达标、法务评审通过**。展开如下。

| 分句 | 具体要做什么 | 当前状态 |
| :--- | :--- | :--- |
| 安全测试全通过 | W4.2 限流 / 黑名单 / 信誉、W7.2 安全加固与隐私、W8.2 安全测试；至少覆盖 [TEST §5](../05-quality/TEST.md) 的伪造种子 / 分片投毒（丢弃 + 拉黑 + 信誉扣分）、索引污染 / 重放（限流 + nonce 去重）、恶意唤醒洪泛（内存不越界、服务不中断）、内存 / 带宽越限（降级链逐层生效） | 组件级有覆盖，**未做整体验收**；判据尚未预注册，须先固定 sha 再采样，不能事后改阈值解释数据 |
| 公测 KPI 达标 | [SRS §4](../01-product/SRS.md) 全局指标：受控环境死种复活实测 100%、唤醒 P95 < 3 s / < 8 s、1 万文件空闲常驻 RSS ≤ 100 MB（72 h Soak）、后台上行 ≤ 配置阈值、搜索有效率 ≥ 95%、旧客户端兼容 100%；另有安装包 ≤ 60 MB 与邀请制公测运行数据（[STATUS-INVENTORY](STATUS-INVENTORY-2026-11-20.md)） | NFR-04 公网唤醒 P95 281 / 230 ms 已关闭；其余公测 KPI 未采。**「公测 KPI」的数值 cutoff 尚未在文档中单独细化**，需先定义公测样本、周期与合格线；外部环境的成功率类指标按 ADR-012 不设数值目标 |
| 法务评审通过 | [LEGAL-REVIEW L1～L6](../07-operations/LEGAL-REVIEW.md) 的书面意见；回填 `spikes.json` 的 `S8.legal_review.written_opinion_received=true` / `resolution=reviewed`；关闭 RISK R-11 | **未开始**。M0 的 `pass` 是所有者豁免，不是书面意见；G4 要求的是「通过」，豁免不能沿用 |

M4 的 WBS 交付物按 [ROADMAP §1/§2](ROADMAP.md)：W4.2、W7.2 / W7.3、W8.2 / W8.3、
安装包、社区运营材料、邀请制公测。R-02 与 R-11 是 **G4 前的 M4 前置收口项**，
不是 G4 三句本身，但会在公测准备期卡住。

## 2. 三项移出功能具体是什么

三项都来自 [ADR-003](../02-architecture/adr/ADR-003-ui-delivery.md) 的
「`coldrevived` + `coldrevive-agent` + 可关 UI」三进程模型。DOC-35 决定 2 已签 B+D：
M3 只交付看护内核 + 纯 Web UI；这三项移出 M3 并挂「M4 再评估」。
**三项都不在 G4 门禁文本内；纳入只会扩大 M4 WBS，不会替代 G4。**

| 功能 | 具体范围 | 当前状态 / 若纳入 M4 要什么 | 建议 |
| :--- | :--- | :--- | :--- |
| 系统托盘 | agent 增加托盘图标、daemon 状态、开 / 关 UI、快速添加任务、异常提示；Win32 / NSStatusItem / StatusNotifierItem 三套 API，Linux 依赖 DBus 与状态栏宿主 | agent 现在是 std-only 看护内核（spawn / try_wait / 重启预算 / 只读 `/health`），无 GUI 依赖。纳入需选 Tauri 或 `tray-icon`/`ksni`，macOS 签名 / 公证证书，三平台验收 | **不纳入**：G4 已重，没有真实桌面分发需求时这是额外平台债 |
| 浏览器下载捕获 | MV3 扩展拦截 magnet / `.torrent` 链接并推到 `/jsonrpc` 建任务；属 FR-22 P2 / W6.5 | G3 的 MV3 插件只验证了「推真实 `.torrent` → daemon 取回解析」，结论是 `accepted_with_gap`，插件不下载内容、未证明自动捕获。纳入需扩展构建 / 权限 / 分发与自动捕获端到端判据 | **不纳入**：不是 G4 条件；现有 RPC 已能让 AriaNg / Aria2 Explorer 接入 |
| UPnP 续租 | 对 IGD / NAT-PMP / PCP 映射做到期跟踪与周期续租，失败回落 relay，写 `/health` 可观测 | `cr-nat` 已有 `upnp.rs` / `natpmp.rs` / `pcp.rs` 原语与 `lifetime_sec`，但 agent 无续租循环；本机 S6 已实测 IGD 与 NAT-PMP 不可用，当前环境无法验证 | **不纳入**：缺真实网关环境，纳入等于先造环境再造功能；若日后有网关，可单独开决定 |

## 3. R-02 复审启动包

R-02 是「公共 KAD 按运营速率发布是否被当污染」。S2 的接纳性已 `pass`，但风险未关闭：
最小样本的拒绝率区间是 `[0, 79%]`（95% 上界），不足以判定。

**判据（来自 RISK §2 三桶，不改）**：

1. 协议层不可解析（`0xE5` / RC4 / 超时 / 未经 HELLO / 未收敛）单独计数，**不进预警分母**；
2. 索引层拒绝（`PUBLISH_RES` 明示拒绝、载荷上限、命名空间 Key 被丢弃）计入预警；
3. 成功为 `PUBLISH_RES` 确认且 `SEARCH_RES` 命中；
4. 第二桶占三桶有效样本比例 **> 20%** 触发预警；
5. 前置条件失败整批 `inconclusive_environment_blocked`，三桶不适用；
6. 至少需要 **10 个以上不同节点** 的接受 / 拒绝计数。

**前置条件（尚未完成，本轮没有执行公共 KAD 发布）**：

- 先把「运营速率」写成预注册判据：样本量、pps、发布库规模、节点选择 / 去重规则、
  时间窗口与 sha 必须固定后才采样；不得看结果改阈值。
- G0 的 `protocol_scope` 放宽只取消行政 BLOCKED，限速、最小样本、**禁止批量发布**、
  R-02 / R-11 与门禁机器常量全部保留。全量共享文件双轨发布属于外部写入，
  需所有者就「运营速率 + 全量双轨」明确授权后才能跑。
- 刷新 `nodes.dat`，用独立出口 / 独立控制端，避免控制 SSH 与被测出口共用 IP
  （此前有 REDIRECT 劫持控制通道失联的教训）；逐轮原始报文与三桶计数一并归档。
- 复审结论只更新 RISK R-02 与 G0-REVIEW 的 M4 复审条目；不自动改 S2 / G2 / G4 门禁字段。
