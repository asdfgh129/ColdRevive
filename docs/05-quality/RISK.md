# 风险登记册（RISK）

> 编号 DOC-13 · 版本 2.0 · 状态 **持续维护** · 责任人 架构组 / 项目组 · 更新 2026-11-09
> 每里程碑末尾复审；等级 🔴 致命 / 🟠 高 / 🟡 中。触发预警后立即在本表更新状态与处置记录。

## 1. 风险矩阵

| ID | 风险 | 概率 | 影响 | 等级 | 缓解措施 | 触发预警 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **R-01** | **冷启动网络效应**：节点太少导致搜不到资源（hMule 复现） | 高 | 致命 | 🔴 | 单机价值优先、生态借力、下载即贡献、渐进式公测（[LLD §13](../03-design/LLD.md)） | 公测复活成功率 < 60% |
| R-02 | 公共 KAD 网络接入受限或专属 Key 空间被视作污染 | 中 | 高 | 🟠 | 命名空间哈希输入隔离、迭代收敛后发布、发布限速、支持 `private` 自建模式（[ADR-001](../02-architecture/adr/ADR-001-kad-network.md)、[PROTO §2.0](../04-protocol/PROTO.md)） | **索引层拒绝率** > 20%（须先排除协议层不可解析 / 静默丢弃 / 未收敛到 tolerance zone） |
| R-03 | KAD / Mainline DHT 双栈复杂度超预期 | 中 | 高 | 🟠 | M0 Spike 先行；失败则收敛单栈 + 映射（[ADR-007](../02-architecture/adr/ADR-007-tracker.md)） | S3 不通过 |
| R-04 | NAT 穿透失败率高，唤醒后连不上 | 中 | 高 | 🟠 | UPnP + 打洞 + LowID 中继；M2 建立 NAT 矩阵 | 公网可达率 < 70% |
| R-05 | BT 引擎不支持按需实例化 / 握手拦截 | 中 | 高 | 🟠 | S1 Spike；备选 libtorrent FFI 或自研精简做种层（[ADR-002](../02-architecture/adr/ADR-002-bt-engine.md)） | S1 不通过 |
| R-06 | 1 万文件内存 / 句柄失控 | 中 | 中 | 🟡 | LRU 硬上限、影子索引、强制切出、Soak 测试 | RSS > 软限持续 5 min |
| R-07 | 造种 I/O 影响前台体验 | 中 | 中 | 🟡 | Idle 优先级、并发 2、去抖、可中断续算 | 前台速率劣化 > 5% |
| R-08 | 索引污染 / 女巫 / 投毒 | 高 | 中 | 🟡 | 命名空间、双重哈希校验、黑名单、限流、信誉 | 校验失败率 > 5% |
| R-09 | 恶意唤醒洪泛 | 中 | 中 | 🟡 | Challenge-Response、nonce、限流、并发上限 | 单 IP 请求 > 阈值 |
| R-10 | 跨协议补源分块不对齐导致返工 | 高 | 中 | 🟡 | 明确排 P2 / v2，先做独立 ADR 与原型（[ADR-004](../02-architecture/adr/ADR-004-ed2k-scope.md)） | 进入 M5 前复核 |
| R-11 | 版权与合规争议 | 中 | 高 | 🟠 | 不内置资源源、白名单共享、举报/黑名单、法务评审（S8） | 法务评审未通过 |
| R-12 | 上游库维护状态 / API 变更 | 中 | 中 | 🟡 | 抽象 `Engine` Trait、锁定版本、保留 FFI 退路 | 关键 crate 停更 |
| R-13 | 关键词精确匹配导致召回率低 | 高 | 中 | 🟡 | 分词多 Key + 归一化 + 模糊重排 + 别名 | 搜索命中率 < 70% |
| R-14 | 用户隐私误发布（共享目录外文件） | 低 | 高 | 🟠 | 白名单强制、唤醒统一 `NOT_FOUND`、日志脱敏 | 出现越界发布即阻断发布 |

## 2. 与 M0 Spike 的映射

| Spike | 覆盖风险 |
| :--- | :--- |
| S1 | R-05 |
| S2 | R-02 |
| S3 | R-03 |
| S4 / S5 / S7 | R-06 / R-07 |
| S6 | R-04 |
| S8 | R-11 |

> Spike 清单见 [TECH-STACK §2](../02-architecture/TECH-STACK.md)，结论出具后必须回填本表等级与状态。

**R-02 观测口径（2026-11-09 修订）**：原「发布失败率」会把协议层与索引层的不同失败混成一个数，
在明文最小客户端下必然产生假阴性。实网小样本须把逐次结果分到三个桶：

| 桶 | 典型原因 | 是否计入 R-02 预警线 |
| :--- | :--- | :--- |
| 协议层不可解析 | `0xE5` zlib 压缩帧、RC4 混淆、超时、未经 HELLO 验证、未收敛到 `SEARCHTOLERANCE` 邻域 | **否**，单独计数 |
| 索引层拒绝 | `PUBLISH_RES` 明示拒绝、载荷上限、命名空间 Key 被丢弃 | **是** |
| 成功 | `PUBLISH_RES` 确认且 `SEARCH_RES` 命中描述符 | 计入成功率分母 |

只有第二桶占有效样本（三桶合计）的比例 > 20% 才触发预警线；第一桶占比过高说明探针能力不足，
应先补协议实现而非判定公共网络不接纳。

**前置条件失败不是一个桶（2026-11-10 P4 实测补充）**：若实验执行环境本身过滤公网
高位 UDP（出站或回程），整次实验应判 `inconclusive_environment_blocked` 并整批作废，
三桶计数全部不适用。判据是「与 KAD 无关的公网高位 UDP 往返也失败」（STUN/19302、
STUN/3478），同时 DNS/UDP-53 正常、LAN 真实 eMule 对同一份 `0xE4 0x01` 能正常应答。
重跑前须先执行 [udp_egress_check.py](../../tests/spikes/s2/udp_egress_check.py)（退出码 0）。
该判定是**逐主机**的：同一网络内不同主机可能有不同出口策略，必须在准备跑 P4 的那台机器上
实测；LAN 内真实 eMule 探测是纯 LAN 流量、未经过公网出口，**不构成**公网可达性证据。
v2.4.9 复核把归因细化为「出口按目标端口/应用白名单丢弃高位未知端口」（53/123 通、
3478/19302 不通），并新增跨主机对照与 `nodes.dat` 新鲜度检查；详见
[PLAN.md §8](../../tests/spikes/s2/PLAN.md)。
**v2.4.10 跨主机复验已闭环**：同一诊断在开了入站映射的 LAN eMule 机器上同样返回
`BLOCKED`（退出码 2，低位 4/4 OK、高位 0/3 OK），按主机的 **STUN** 出站例外假设被否证 ——
入站 DNAT 不产生 STUN 出站例外。
**v2.4.11 归因收窄**：STUN 是代理指标、不等于 KAD；本机已用真实 `0xE4 0x01` 对 3 个较新
公网联系人（含标准 `4672`）在临时 / 固定源端口下复测，均 **0/3** 无响应，故**本机**前置
条件失败成立；LAN eMule 主机显示 HighID 与 432 个 KAD 联系人，其 KAD 是否存活、出口是否
按应用或按 IP+源端口放行仍未判定，须补 `Kad 网络` 面板状态并在该机运行
[`kad_egress_probe.py`](../../tests/spikes/s2/kad_egress_probe.py)。详见
[PLAN.md §8.6](../../tests/spikes/s2/PLAN.md)。
**v2.4.12 面板证据 + 源码复核**：该机 `Kad 网络` 面板 `状态` / `UDP 状态` 均为「打开」、无
Buddy 行，firewalled / 陈旧路由表假设被否证；但 aMule 源码显示 KAD UDP 防火墙检测是
「远端向本机公网 IP:KAD 端口发无载荷入站 UDP 包」，由入站 DNAT 即可通过，协调走 TCP，
`m_firewalledUDP` 初值还是 `false` —— 因此「打开」是**入站可达性**结论，与「出站高位 UDP
被过滤」可同时成立，**不证明该机能跑 P4**。新假设「出口统一过滤出站 + DNAT 产生打开」
无法排除。决定性核实仍为在该机运行 KAD 专用探针（退出码 `0` 是充分证据、`2` 不是充分
否证）并查看 KAD 收发包计数是否增长；详见 [PLAN.md §9](../../tests/spikes/s2/PLAN.md)。
**v2.4.13 跨主机 KAD 探针已执行**：该机 0/3 / 退出码 2；但两次 0/3 共用同一份 3 目标、
不是独立复现，新增 [`bootstrap_res_to_targets.py`](../../tests/spikes/s2/bootstrap_res_to_targets.py)
从 03:12 UTC 新鲜 `BOOTSTRAP_RES` 取 10 个公网联系人（与旧目标重叠 0/10），本机宽扫
0/10。另按 eMule 官方帮助区分：下载走 TCP 且「与网络选择无关」，`Server`/`Global (Server)`
搜索走 eD2k 服务器 TCP，只有 `Kademlia` 方法要求 UDP 通 —— 故「eMule 下载/搜索正常」
**不构成** KAD 出站证据，应为「明确选 `Kademlia` 方法搜热门词」。工程决策已与归因解耦：
本网无独立客户端被证明可跑 P4，**换网重跑**，剩余核实只用于收窄归因。详见
[PLAN.md §10](../../tests/spikes/s2/PLAN.md)。
无论哪种情况都不得重试计数或据此判定 S2；换网后仍须刷新 `nodes.dat`。
详见 [PLAN.md §7](../../tests/spikes/s2/PLAN.md)。来源：[PROTO §2.0](../04-protocol/PROTO.md)、
[S2 排期 §0](../../tests/spikes/s2/PLAN.md)。

## 3. 顶层三项

评审时优先关注这三件事——技术路径在讨论中已被论证为自洽且可行，剩下的不是「能不能做」，而是：

1. **R-01 冷启动网络效应**（唯一 🔴，非技术风险，决定项目存亡）。
2. **R-05 / S1**（BT 引擎能力是否支撑 LRU 与握手拦截，决定架构是否需要重做）。
3. **R-02 / S2**（公共 KAD 是否接纳专属命名空间，决定「生态借力」策略是否成立）。

## 4. 维护规则

- 状态流转：`开放 → 缓解中 → 已关闭` 或 `开放 → 已发生（触发预案）`。
- 每里程碑末尾由架构组复审概率/影响，更新等级并追加处置记录。
- 新风险须关联至少一个 ADR 或 [OPEN-QUESTIONS](../06-plan/OPEN-QUESTIONS.md) 条目，避免悬空。
- 已关闭风险不删除，保留复盘价值。
