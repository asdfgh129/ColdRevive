文档工程规范与工作流

Docs as Code：Markdown 是唯一事实来源，HTML 是构建产物。

目录层级： 01-product 产品与需求 · 02-architecture 架构与决策 · 03-design 详细设计 · 04-protocol 协议与接口 · 05-quality 质量保障 · 06-plan 计划跟踪 · 07-operations 发布运维 · 08-reference 参考资料 · 09-archive 归档基线。 工程目录另有 src/ tests/ scripts/ config/ .github/workflows/。
规范项约定
唯一事实来源docs/**/*.md；生成的 .html 由 .gitignore 排除，禁止直接编辑
Front Matter每份文档含 doc_id / title / category / version / status / owner / updated，CI 校验
交叉引用一律相对路径，禁止绝对本地路径与外链短链；引用具体章节只写编号不复制正文
决策留痕每个技术抉择独立成 ADR；已接受的 ADR 不改正文，变更时新增并标注「已取代」
归档规则被取代版本移入 09-archive/ 并标注废止，只读引用，冲突时以现行文档为准
协议演进PROTO 任何变更须递增 PROTOCOL_VERSION 并新增 ADR

构建与校验

# 由 Markdown 生成各文档配套 HTML 页面（不覆盖本索引页）
python3 scripts/build_docs.py

# 仅校验 front matter 与相对链接（CI 使用）
python3 scripts/build_docs.py --check

# 依赖
python3 -m pip install markdown

构建器除生成独立 HTML 外，还会把全部文档正文与源码写入本页的 DOCS_PAYLOAD 数据块，因此单独复制 index.html 一个文件也能读完全套文档。修改 .md 后必须重跑构建，否则本页内嵌内容不会更新。新增文档需同步三处：docs/README.md 编号表、本页 DOCS 清单、CHANGELOG.md。
